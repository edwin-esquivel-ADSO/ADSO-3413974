# 🗺️ Mapa de Procesos

## ¿Qué es?
Un **mapa de procesos** es una representación visual de las actividades, tareas y flujos de trabajo de una organización. Muestra **qué se hace, cómo se hace y quién lo hace**.

---

## ¿Para qué sirve?
- Identificar ineficiencias y cuellos de botella
- Estandarizar procedimientos
- Facilitar la comunicación entre áreas
- Apoyar la mejora continua y auditorías
- Onboarding de nuevos colaboradores

---

## Tipos de Mapa de Procesos

| Tipo | Descripción |
|------|-------------|
| **Mapa de alto nivel** | Vista general, sin detalle. Ideal para gerencia. |
| **Mapa detallado** | Paso a paso, incluye decisiones y responsables. |
| **Diagrama de flujo** | Usa símbolos estándar (ISO/ANSI) para representar el flujo. |
| **SIPOC** | Suppliers, Inputs, Process, Outputs, Customers. Vista macro. |
| **Swimlane (carril de nado)** | Muestra responsables por área en carriles horizontales. |
| **Mapa de valor (VSM)** | Visualiza el flujo de valor e identifica desperdicios (Lean). |

---

## Símbolos Básicos (Diagrama de Flujo)

| Símbolo | Significado |
|---------|-------------|
| **Óvalo** | Inicio / Fin |
| **Rectángulo** | Actividad o tarea |
| **Rombo** | Decisión (Sí / No) |
| **Flecha** | Dirección del flujo |
| **Paralelogramo** | Entrada / Salida de información |
| **Cilindro** | Base de datos |

---

## ¿Cómo hacer un Mapa de Procesos? (Pasos)

1. **Definir el alcance** → ¿Qué proceso se va a mapear?
2. **Identificar el equipo** → ¿Quiénes participan?
3. **Listar las actividades** → ¿Cuáles son los pasos?
4. **Establecer el flujo** → ¿En qué orden ocurren?
5. **Asignar responsables** → ¿Quién hace qué?
6. **Validar con el equipo** → ¿Es correcto y completo?
7. **Documentar y publicar** → Compartir con los involucrados

## Herramientas para crearlo

- **Lucidchart** – Online, colaborativo
- **Draw.io (diagrams.net)** – Gratuito
- **Microsoft Visio** – Profesional
- **Miro** – Colaboración en tiempo real
- **Bizagi** – Especializado en BPMN
- **PowerPoint / Google Slides** – Básico pero accesible

---

## Buenas Prácticas

✅ Usa símbolos estándar y consistentes  
✅ Mantén el diagrama simple y legible  
✅ Incluye el nombre del proceso, versión y fecha  
✅ Valida con quienes ejecutan el proceso  
✅ Actualiza cuando el proceso cambia  
❌ No incluyas demasiado detalle en un solo diagrama  
❌ Evita ambigüedades en las decisiones  

---

## Ejemplo: Proceso de Atención al Cliente

```
INICIO → Recibe solicitud → ¿Es urgente?
           ├─ SÍ → Escalar a supervisor → Resolver en < 1h
           └─ NO → Asignar a agente → Resolver en < 24h
                         ↓
              ¿Cliente satisfecho?
                ├─ SÍ → Cerrar ticket → FIN
                └─ NO → Revisar y escalar → Resolver → FIN
```
